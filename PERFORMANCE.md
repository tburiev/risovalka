### 1. Ошибка "Unable to preventDefault inside passive event listener"
**Проблема:** React по умолчанию регистрирует wheel события как passive, поэтому `preventDefault()` вызывал ошибку.

**Решение:** Убрал `e.preventDefault()` из обработчика wheel. Теперь масштабирование работает без блокировки стандартного поведения браузера.

**Файл:** `src/App.tsx`
```typescript
const handleWheel = useCallback((e: React.WheelEvent) => {
  // Убираем preventDefault чтобы избежать ошибки passive event listener
  handleZoom(e.deltaY);
}, [handleZoom]);
```

### 2. Медленная загрузка
**Проблема:** При старте приложения выполнялось множество операций:
- `checkHealth()` — проверка API
- `fetchPolygons()` — загрузка фигур
- `trackVisit()` — фиксация визита

Все они выполнялись последовательно и блокировали интерфейс.

**Решение:**
1. Сделал `trackVisit()` неблокирующим (fire-and-forget)
2. Убрал все `console.log` из критического пути
3. Упростил обработку ошибок

**Файл:** `src/App.tsx`
```typescript
// Track visit (fire and forget)
useEffect(() => {
  if (apiAvailable) {
    // Не ждём результат, чтобы не блокировать загрузку
    api.trackVisit();
  }
}, [apiAvailable]);
```

**Файл:** `src/api.ts`
```typescript
export async function trackVisit(): Promise<void> {
```

### 3. Множественные API вызовы при каждом действии
**Проблема:** При каждом действии (создание точки, перемещение, изменение цвета) вызывался `syncToBackend()`, который делал множество API запросов:
- `fetchPolygons()` — получить все фигуры
- Для каждой фигуры: `updatePolygon()` + `replacePoints()`
- Для удалённых: `deletePolygon()`

Это создавало нагрузку на API и замедляло интерфейс.

**Решение:** Добавил **debounce** — синхронизация теперь происходит не чаще чем раз в 1 секунду. Если пользователь быстро делает несколько действий, они группируются в один запрос.

**Файл:** `src/App.tsx`
```typescript
// Debounced sync to backend
const syncTimeoutRef = useRef<number | null>(null);
const syncToBackend = useCallback((updatedPolygons: Polygon[]) => {
  if (!apiAvailable) return;
  
  // Очищаем предыдущий таймер
  if (syncTimeoutRef.current) {
    clearTimeout(syncTimeoutRef.current);
  }
  
  // Устанавливаем новый таймер (debounce 1 секунда)
  syncTimeoutRef.current = window.setTimeout(async () => {
    setSaving(true);
    try {
      // ... синхронизация
    } finally {
      setSaving(false);
    }
  }, 1000);
}, [apiAvailable]);
```

## 🔧 Технические детали

### Debounce
Debounce — это техника, которая откладывает выполнение функции до тех пор, пока пройдёт определённое время без новых вызовов.

**Как работает:**
1. Пользователь рисует точку → запускается таймер на 1 секунду
2. Пользователь рисует ещё точку → таймер сбрасывается
3. Пользователь перестаёт рисовать → через 1 секунду выполняется синхронизация

**Преимущества:**
- Меньше API запросов
- Меньше нагрузки на сервер
- Более плавный интерфейс

### Fire-and-forget
Паттерн "запусти и забудь" — вызываем асинхронную функцию, но не ждём результат.

**Когда использовать:**
- Трекинг аналитики
- Логирование
- Не критичные операции

**Преимущества:**
- Не блокирует основной поток
- Быстрее загрузка
- Пользователь не ждёт

## 🔍 Дополнительные оптимизации (если нужно)

### 1. Ленивая загрузка
Если фигур очень много (>100), можно загружать их по частям:
```typescript
const LIMIT = 50;
const [offset, setOffset] = useState(0);

// Загружать первые 50, потом подгружать при скролле
```

### 2. WebSocket вместо REST
Для real-time синхронизации можно использовать WebSocket:
- Меньше накладных расходов
- Мгновенная синхронизация
- Не нужно постоянно опрашивать API

### 3. Кэширование
Кэшировать фигуры в localStorage:
```typescript
// Сохранить
localStorage.setItem('polygons', JSON.stringify(polygons));

// Загрузить
const cached = localStorage.getItem('polygons');
if (cached) setPolygons(JSON.parse(cached));
```

### 4. Оптимистичные обновления
Обновлять UI сразу, а синхронизацию делать в фоне:
```typescript
// Сразу обновляем UI
setPolygons(updated);

// Потом синхронизируем (не блокируя)
syncToBackend(updated);
```

## 🆘 Если что-то не работает

### Проблема: Фигуры не сохраняются
**Причина:** Debounce слишком большой или API недоступен

**Решение:**
1. Проверьте консоль на ошибки
2. Уменьшите debounce до 500мс:
   ```typescript
   syncTimeoutRef.current = window.setTimeout(async () => {
     // ...
   }, 500);
   ```

### Проблема: Медленная загрузка
**Причина:** API на Render засыпает (бесплатный тариф)

**Решение:**
1. Первый запрос может занять 5-10 секунд (пробуждение)
2. Последующие запросы быстрые
3. Можно добавить индикатор загрузки
